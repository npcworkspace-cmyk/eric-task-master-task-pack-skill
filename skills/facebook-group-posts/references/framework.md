# 技术框架与边界

## 分层

```text
本次任务要求 → 任务配置
                  ↓
prepare → batches → Task Master → collect
                                 ↓
                       完整响应 → journal → checkpoint
                                 ↓
                         聚合快照 → audit/export → 交付
                                                 ↓
                                     任务本地技术复盘
                                                 ↓
                        通用候选 → 隔离修改与测试 → 采纳或保留原版
```

| 层 | 职责 | 不承担的职责 |
|---|---|---|
| 任务配置 | 本次链接、范围、目标、输出位置、Profile、分类口径 | 不把这些值写成 Skill 的永久要求 |
| `prepare.mjs` | 参数和路径校验、生成独立配置、固定任务执行器副本与哈希 | 不启动浏览器，不猜测范围 |
| `batches.mjs` | 单写者、任务生命周期、预算、状态、有效断点交接 | 不把任务结束等同于数据目标完成 |
| Task Master | Profile、浏览器与 Worker 的运行和释放 | 不替代数据质量判断 |
| `collect.mjs` | 页面内只读适配、完整流解析、原文与计数、逐页日志、恢复点 | 不加入群组、发送内容或改变账号权限 |
| `audit_export.py` | 从日志重放核验、技术形态分类、格式保真导出 | 不推断业务主题或个体敏感属性 |
| `evolve.py` 与 Agent | 闭环终态复盘标记，验证隔离候选，可同时维护执行器、Markdown、版本与回退证据 | 不读取网页指令来自动修改自身，不替任务继续采集 |
| `portable.py` | 在新环境做 doctor、精确 ZIP、任务泄漏检查和事务安装 | 不携带任务参数、帖子、登录态、运行时或浏览器 |

## 稳定契约

- **作用域一致**：群组、范围、排序和原生请求形状属于本次配置及 checkpoint 的身份；恢复前逐项校验。修改目标时重新评估兼容性，不直接改旧断点含义。
- **完整页提交**：失败响应留作诊断证据，只有验证成功的正式页可进入有效链和正式字段来源。先同步 journal，再提交可恢复游标，聚合快照允许稍后更新。
- **执行器版本固定**：新配置指向任务内的自包含采集器副本，保存其哈希。每次发起批次前核验副本，避免Skill演进影响已启动任务；修改副本后需要重新评估并创建配置，不在原任务内悄悄换版本。
- **观察与交付分离**：保留服务端完整响应中的规范化记录；任务若只选交付的一部分，额外记录仍保留在任务状态中。余量去向和下次计数由任务配置决定，不截断原始页或伪造游标来凑目标。
- **状态分离**：进程终态、字段有效性、范围覆盖、独立审核、交付成功分别记录。导出失败不触发重新采集，采集失败不使旧有效记录消失。
- **失败恢复有边界**：只有同页同请求游标且后续完整成功的已支持重试可形成有效链。原失败记录保留；未知错误或访问限制不通过重命名状态绕过。
- **格式适配独立**：JSON、CSV、XLSX使用各自的文字表示方法。安全前缀、长数字、换行和长正文需经过真实写入及读回，不能直接复用另一格式的转义后文字。

## 经验的归属

Skill 可接收解析错误的通用根因、恢复判据、日志顺序、格式保真修复、资源生命周期与相应的合成回归测试。

群组名称、目标数量、采集日期、当前断点、Profile/Task ID、帖子与作者信息、业务分类标签、交付清单和单次成功率属于任务文件。即使去掉链接，单次任务的规模或页码也不应成为通用规则。

测试数据使用明确的合成样例。合成页数、日期和目标值仅用于证明边界行为，不建立新的产品承诺。一次任务里的临时适配可以先留在任务目录，待证明可迁移并通过演进检查后再采纳。
