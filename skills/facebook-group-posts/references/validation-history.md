# 验证方法与能力边界

Skill只保留技术结论与可复现的合成测试。真实任务的链接、规模、日期、页码、Profile、结果数字和原始诊断留在各任务目录；不能将其改写为通用需求。

## 分开记录的验证层次

| 层次 | 可以证明 | 不能据此声称 |
|---|---|---|
| 参数与格式检查 | 名称、结构、编码、路径、配置约束合法 | 真实站点字段仍然匹配 |
| 合成collector测试 | 完整流解析、提交顺序、恢复判据、失败观测隔离 | 账号可访问任意群组 |
| 模拟Task Master调度 | 批次生命周期、停止、未知启动、Profile与Manager变化处理 | 真实浏览器及其权限已检查 |
| 真实文件写回 | JSON/CSV/XLSX主键、原文、空值、长文和公式样式字符保真 | 原始页面本身没有缺漏 |
| 可携带发布测试 | manifest 精确成员、路径安全、任务泄漏闸门、确定性 ZIP 与隔离目录安装 | 未实际运行过的操作系统已经兼容 |
| 独立离线演练 | 从任务配置经过核心模块形成可审核交付 | 已完成线上页面抽查 |
| 本次任务有界线上校准 | 当时群组、语言和页面结构下的字段适配 | 后续所有群组与结构永久可用 |

## 已沉淀的技术判据

- 同一响应的全部frames必须合并验证，完整响应和有效分页信息是提交前提。
- 完整成功日志是正式记录来源；失败观察可保留证据，不能污染正文、计数、去重或首次出现顺序。
- 恢复依据真实cursor及完整日志链。暂时空结束或普通截断的成功重试只按严格同页同游标条件采纳；不同请求或普通成功重复不能隐藏。
- journal先于checkpoint持久化；快照落后时重建数据，Windows原子替换仅有限重试。
- Profile和Manager身份属于运行生命周期；未知启动结果和人工取消不能触发自动重复任务。
- 时间回跳与范围覆盖分开判断；不能用单条旧帖或任务结束证明全部目标完成。
- 输出格式独立编码；实际读回检查必须保留原始引号、公式样式开头、长ID和超长文字。
- 终态监督器必须生成 pending 复盘标记；`evolve.py review` 生成收据后才标 completed。执行器和 Markdown 改进使用同一候选、验证、采纳与回滚事务。
- 发布 ZIP 只含 manifest 声明的通用文件；目标、范围、Profile、预算、断点、帖子、收据及设备绝对路径均留在任务或本机配置中。

这些技术结论进入源码、文档和合成回归。一次任务的成功率、页数、数据量及业务分类不进入Skill。

## 演进验证

每次任务的技术复盘按 [演进机制](evolution.md) 留在工作目录。只有最小复现、修复、验证和差异审阅形成闭环后才采纳技术更新；无有效新经验保持当前版本。对解析、恢复、审计等关键逻辑的改动，应安排独立离线演练；只有本次任务本来需要线上校准时才使用Task Master，不为文档更新重复采集。

发布时的具体离线测试结果见 [离线验证记录](offline-validation.md)。没有再次进行线上采集的版本必须明确保留这一边界。

## v1.2.0 可携带升级

- Windows 主机实际运行 collector 21、batch supervisor 23、audit/export 43、evolution 21、portable 11，共 119 个离线用例；没有启动浏览器或线上采集。
- 新增 Task Master 的显式参数、环境变量和 PATH 发现；`maxPages` 改为每次任务必填，移除历史分批数默认值与固定上限。
- 监督器终态会生成 pending 复盘标记，review 收据闭环 completed；执行器与 Markdown 继续受同一候选验证、独立测试差异审核、备份和回滚约束。
- manifest、确定性 ZIP、恶意成员拒绝、设备 Home 路径/具体群组 URL/任务 token 泄漏闸门，以及临时 Skills 目录安装与替换备份均有合成回归。
- macOS 与 Linux 尚未在对应实机运行本版，因此只声明代码使用跨平台路径/进程接口并已被离线审阅；实机兼容需在对应主机运行完整 smoke 矩阵后更新记录。
