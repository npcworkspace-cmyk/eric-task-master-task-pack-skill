# 每轮复盘与通用迭代

完成、部分完成、暂停、失败都做离线复盘；复盘不自行扩大配额、恢复浏览器、解除验证或发布。输入来自本轮 Brief、账本、原始证据、审核记录、基线、候选框和指标，输出留在任务目录。

## 本轮先核事实

1. 核对正式新增、溢出、补证、未知/未审、无效观察、未启动、Task Master 终态与业务缺口。运行 `ig-audit.mjs`，读实际文件，不以 Worker 成功替代业务验收。
2. 分问题类型：入口不可用、加载/访问限制、采集器解析缺陷、身份/去重错误、主题漂移、证据不足、审核口径冲突。根因未知就保留未知；一个账号失败不推成平台普遍规律。
3. 分别展示首次归属、路线独立召回、重复、审核覆盖、个人/团队种子和中转，以及发现/补查/诊断/审核的成本。未测成本不补估计；仅候选吞吐不能替代合作名单收益。
4. 比较策略时注明种子、顺序、预算与冻结框。配对校准、后期扩量和目的性补查分别报告；把本轮观察与仍需实验的假设分开。

## 三方面都作决定

在任务 `iteration.json` 记录 `briefVersion, rubricVersion, skillVersion, moduleSha256, baselineSha256, evidenceRefs, methodology, executor, strategy, nextAction`。每个方面保存 `decision=no_change/candidate/validated/adopted/rejected, reason, evidence, changedFiles, checks, remainingLimits`；不能只有“已复盘”或空 pending。

- **方法文档：** 是否出现重复误解，缺字段或错误判断规则。修规则的条件与语义，不写某个客户/账号的固定结论。
- **执行器：** 是否有可复现解析、预算、日志、恢复、停止错误。用最小失败样例和必要的离线/浏览器验证修复，不能删失败测试或弱化断言来通过。
- **策略：** 是否值得调整当前有权执行的入口顺序、种子范围或补证顺序。一次产量高、样本小或未审核不足以形成全局优先策略；先留下有界实验计划。

下一步选择继续一轮、先补筛、重找参考/查询或结束。新种子须经过本轮标准审核；限定中转写具体作者/内容范围。连续开发已经获授权时自动衔接，目标、Profile、预算和用户约束仍保持。

## 隔离、验证和部署

把候选修改放在独立副本，保留当前完整单元的版本与哈希。实际测试修改的行为和失败边界，检查自包含 Task Master 入口、相对资源引用、输入外置、测试断言变化和打包文件；不要把任务输出、登录状态或本机路径带入 Skill。

方法改动做一个真实请求的前向演练，由独立审阅者查看输入与最终产物，指出失配；提取器/对账改动使用针对缺陷的合成样例。合成数据只证明实现逻辑；历史浏览器成功只证明当时那份模块，不自动证明新版本或所有系统实跑。

有有效修改且任务授权更新时，按完整 Skill 备份 → 校验候选 → 安装 → 比对哈希 → 生成可移植包与回滚包。使用 `skill-creator` 的格式检查和 `task-pack-audit` 八原则审计（可用时）；不强制建立新控制器、策略服务或多个 IG Skills。没有有效改进记录 no_change 与依据，不为复盘而改代码。

下一轮固定已采用版本和实际模块哈希，加载新的任务基线；不能让运行中任务静默切换。源文件、安装副本、ZIP 和真实浏览器验证分别报告；未测系统不称已验证，未有 Git remote/发布授权不称已推送。回退时只恢复本次 Skill 完整单元，不改用户任务数据或浏览器 Profile。
