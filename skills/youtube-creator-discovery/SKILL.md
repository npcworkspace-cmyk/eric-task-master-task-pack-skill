# YouTube 红人发现与裂变

公共发行与当前验证边界见[版本说明](references/validation-scope.md)。

从需求与参考研究开始，成批采集最小证据，集中判断主题和角色，只展开已经审核且有新线索的对象。一个独立 Skill 配一个执行 Pack；不依赖 IG/TK 的代码，也不另建浏览器控制器。

## 开始与选路

沿用已有需求、参考和授权，将产品、主题、参考用途、数量口径、必要地区/语言/订阅量条件、内容窗口、Profile、基线和预算保存为版本化 Brief。缺项只有会改变目标或权限时才提问；未提出的国家、粉丝和商务要求保持未限定。用户授权自行选样时标记 `assistant_selected_experimental_reference`，不能写成客户事实。

记录本轮是入口验证、候选发现还是全量筛选，以及 N 指发现频道还是满足声明条件的频道。用户硬条件与 Agent 为取证采用的判断方法分开；作品条数、样本量和主体排除条件不能从某次试跑变成通用硬门槛。抽样可以完成声明的验证范围，不能替代用户要求的全量筛选。

3–5 条参考是研究建议，不是强制数量。区分竞品、品牌已合作、内容风格、创作者与中转。先核对本人身份，采近期作品元数据及代表作品描述；采样范围与完整窗口覆盖分别声明。标题、简介、描述中的“亲测”“原创”“合作”是待核声明；讲解风格、原创实拍、真实性和受众需要相应证据。无需每次下载所有视频。

选入口时读 [发现手册](references/discovery-playbook.md)。先小批验证当前网页，再扩量。频道搜索、视频作者、播放列表整理者、列表内作者、播放页推荐、明确提及是不同关系。广告、仅被提及而未观察本人的账号、普通评论者不能直接变成红人候选。

Shorts 卡片可能没有作者。保留视频与未解析记录，打开该条视频并核对精确 video ID 后归属频道；只有本人 Shorts 页可以用已核对的主页 ID 归属。保留短视频格式和原始 Shorts URL，作者解析成本归原发现路线。

## 执行 Pack

首次执行读取 [Pack 契约与命令](references/pack-contract.md) 和本机 `eric-task-master` 当前 Skill。浏览器只用 Task Master 的自包含 `scripts/browser.mjs`；Manager 管理 Chrome/Profile/任务生命周期，模块负责平台动作、节流、证据、预算与检查点。`scripts/process.mjs` 做本地去重、来源聚合、入口统计与可复现抽样。

沿用用户已指定的 Profile，显式传 `--profile`。未指定时按当前 Task Master 接入说明处理；不将此包作者的路径或 Profile 写进通用配置。同一 Profile 浏览器串行，离线处理可以并行。启动后立即提供 Dashboard URL 并持续 follow，不能将任务提交视为完成。

所有任务必须有有限动作、滚动/卡片上限、总时间和数量目标。先持久化当前页面证据，再推进进度。恢复读取既有证据与完成标记；未完成动作从原入口重放并去重，本版本不承诺续接原生分页 cursor。不能把重放称为精准续页。项目合同不一致时报错，不覆盖既有成果。

遇验证停止派发并调用 Task Master `wait({reason:'verification'})`；按其截图/人工恢复机制处理。403/429、登录或同意页自动停止当前批次；结构异常保存该动作的 partial/failed，Agent 看到持续同类错误时暂停剩余队列再诊断。不得切换 Profile、账号或线路绕过。用户暂停或取消时保存 checkpoint 与可用结果，取消不删除产物。

## 集中审核与一轮展开

以固定 rubric 分开判断：主题与内容形式、创作者/团队/品牌/店铺/媒体/未知角色、合作条件、发现价值。自动文字信号只用于排队，不能伪装成 Agent 语义审核。证据不足为 pending；未知地区、受众、订阅量或报价不得补零或推断通过。品牌与店铺允许成为有范围的中转，不计个人红人通过。

审核需要持续主题时检查多条不同作品及主页。审阅结论保留频道 ID、rubric 版本、证据文件、原文摘录、判断理由与缺口。只看元数据时写清这一层级，不声称观看了视频。合作资格与可展开价值独立；主题种子不代表商务通过。

成批发现后先复用已存的全部本人作品和来源去重审核，再针对 pending 的缺失条件补证。首批近期作品没提到某产品，只说明当前采样未证实，不自动证明整个频道没有该分支。未审核与已审核但待补证分别建队列；补证后追加新判断版本，不改原观察。`process.mjs` 可对齐 Agent 已作出的审核决定并输出四种状态及待办，不能代替语义审核。

下一批动作由已审种子或明确查询线索产生，带父种子、来源作品/证据、关系、深度与预算。相同动作只执行一次但保留所有来源。首次搜索根为深度 0；从参考内容推导的发现可记源路径，轮次、翻页和缓存复用不增加真实账号跳数。未审的新候选不直接递归展开。

## 判断入口收益与收尾

同时比较路线独立去重新增、正式池首次贡献、重复/未解析比例、固定样本主题通过、可展开主体和成本。首次贡献受执行顺序影响，应交替同源查询或同组种子的先后顺序。样本只代表已观察框；未审全池不计不合格。发现动作、补资料、审核、失败、等待和历史证据准备成本分开，缺测留空。

进度和收尾同时给出正式候选、已审核、通过、待补查、明确不符、未审核及其分母。样本审核完成、全池审核覆盖和必要条件判定完成分别报告。路线等额样本不给整池命中率；判断标准、品类或采样框不同的轮次不直接比较升降。具体抽样与对账选项见 [Pack 契约](references/pack-contract.md)。

达到 N 个发现账号后停止增加，继续完成已授权的集中审核、复盘和交付；超出 N 的尾部观察单列溢出。队列耗尽但未达目标为 partial，Worker finished 不等于业务 complete。交付规范与身份规则见 [数据契约](references/data-contract.md)。

每次完成、暂停或失败后检查 Markdown、执行器和入口策略是否有可复用改进。仅将有证据的问题做最小修改；没有则记录 `no_change`。任务品牌、查询、Profile、阈值和结果留在任务目录。候选先在隔离副本验证，执行 `node --test scripts/behavior.test.mjs` 及 Skill 校验，再按 `task-pack-audit` 检查完整单元；保留旧安装和回滚路径。源码/本机安装/ZIP 的哈希分别核对。离线通过、Windows 真浏览器实测、其他系统未测分别声明。

默认只读发现和本地交付。公开商务入口可以记录，不猜测邮箱，不绕过邮箱显示验证。关注、点赞、评论、邮件、私信、提交合作或发布均需相应明确授权。
