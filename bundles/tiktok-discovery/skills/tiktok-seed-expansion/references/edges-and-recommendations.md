# 推荐卡片、来源边与深度

## 推荐账号是独立账号入口

读取来源主页实际展开的推荐区域；展开、翻页或“查看全部”以当前页面结构为依据，人形加号等图标只有实际含义确认后才操作。不点击卡片“关注”，不把全页所有 `/@` 链接都当推荐账号。

记录真实目标链接、可见账号/昵称、显示顺序、推荐理由原文、来源主页、区域名称、观察时间、动作 ID 和证据路径。卡片可无作品 ID，不为入库补造视频；粉丝/bio 未知直接进入批量资料补查。出现顺序是页面次序，不是精准度分数。

正常加载响应只能补充与同次可见卡片/作品匹配的字段，不将未匹配响应内容算成候选。区域未出现、加载失败、入口不可用、列表结束与预算停止单独记状态；单次没出现模块不能等于该账号没有推荐。

关系记录为 `profile_suggested_accounts` 或契约对应类型，含义仅是“在该主页观察到推荐”。重复出现在不同主页不能自动变成独立背书；算法可能结合查看者与其他上下文，需用本轮主题命中和资格结果评估实际收益，不能先称“非常精准”。

## 去重而不丢来源

| 对象 | 合并依据 | 保留内容 |
|---|---|---|
| 账号 | 优先稳定平台 ID；只有 handle 时标身份未确认 | handle 历史、别名、首次观察、最新资料、原始证据和冲突 |
| 作品 | 平台作品 ID；备用 URL 标识保留不确定性 | 作者、全部来源、原文、发布时间/指标观察时间 |
| 动作 | 规范化查询或 URL 及当前实现实际纳入的上下文 | 路线、排序、筛选、范围、来源、预算、checkpoint、重查原因 |
| 来源边 | 真实父身份、目标身份、路线和来源证据 | 原文/URL、作品/动作、轮次、时间、证据路径与路径身份 |

真实字段和去重键以 [运行库契约](../../tiktok-seed-discovery/scripts/runtime/CONTRACT.md) 为准。仅修改未参与动作键的排序、路线或预算元数据，不能视为新动作。多个父来源共用一次执行时保留每条来源边。

固定基线包括此前全部候选、中转和参考本人，不只最终名单。稳定身份只计一次，但原始 handle 记录及作品归属仍保留；alias/ID 冲突显式输出，不能凭显示名静默合并或改写旧归属。冲突先核验再用于精准新增或路径统计。

## 从真实账号路径计算深度

搜索发现的根账号 A0 深度为 0。A0 的证据产生动作且真实观察到 A1，才形成一跳；随后用 A1 自己的新证据展开到 A2 才是第二跳。参考 → 查询的来源链保留，但参考研究、查询、标签、作品、分页不是额外账号跳数。

每条边有真实父节点与来源语义；搜索相关不标成关注，品牌提及不标成合作。回到祖先、同账号别名、重复账号和重跑同缓存不增加无重复路径深度。多父来源保存各条可验证路径，不能直接取最大父深度加一后当成所有方向已完成。

`author.depth` 若为最小观察深度，只反映最短已知来源路径，不能代表最长实际深挖。逐根方向从身份去重后的来源图核算最长无重复账号路径、证据与停止原因；业务轮次编号不能替代证明。6 跳需要 7 个不同账号与 6 条真实、可追溯的展开边。

主页推荐动作若采用 `kind:"profile",route:"profile_suggested_accounts"`，按契约区分父账号深度与卡片作者深度；不能在输入和入库时重复加一。执行实现、当前页面支持、实际成功证据与最终业务收益分别记录。
