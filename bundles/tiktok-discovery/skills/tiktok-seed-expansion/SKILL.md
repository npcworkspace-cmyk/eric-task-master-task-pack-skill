# TikTok 种子裂变

一轮展开一批，经审核后把新的可靠种子交回同一机制。用户授权持续开发时可连续多轮，每轮仍保留独立来源、审核、绩效和继续/停止决定。三 Skill 的完整流程是 [参考研究与种子发现](../tiktok-seed-discovery/SKILL.md) → 本 Skill → [复盘与迭代](../tiktok-discovery-retrospective/SKILL.md)。

## 输入与准入

读取当前 Brief、参考研究底稿、已审核种子及发现价值理由、真实作品/bio/推荐来源、历史身份和作品基线、动作账本、轮次与路径、预算及用户选择的 Profile。已有需求与授权直接沿用，不重新向客户索取已给过的四项。新方向缺 Brief、参考或可靠种子时回到第一 Skill。

画像符合度与展开价值独立。主题及线索足以探索时，地域、商业等未知可有限展开，但不能计资格通过。品牌、机构或粉丝范围以外者可以有中转价值；明确无关、无有用线索的账号停止。未审核账号清单先补必要证据，不默认每人都值得展开。

每次运行前加载第三 Skill 已验证且当前适用的抽象策略；本轮具体品牌、国家、账号和关键词仍在本轮数据中。单次表现较好、缺少验证的改进不得直接升为全局默认。

## 五类入口批量展开一轮

从种子实际证据中选择有效线索，不强迫每个种子具备五类入口，不默认每人再采 100 条。优先复用现有可靠资料；只有会改变展开决策的缺口才补采。

| 入口 | 允许的来源 | 判断边界 |
|---|---|---|
| 标签 | 本人真实作品标签与已审核主题簇 | 同标签不证明合作或同受众；推导查询另标 |
| 身份/地域 | 本人 bio、作品可引用的身份与地点文字 | 只产生搜索线索，所在地和受众资格分别审核 |
| 生活场景 | 真实作品的任务、问题、环境与使用情境 | 同义改写保留原词和推导关系，不引入无据身份 |
| 品牌/产品 | 真实名称、产品使用、披露与参考研究关系表 | `mention/product_use/gifted/paid_partner/self_brand/unknown` 分开，不能把提及网叫合作网 |
| 主页推荐账号 | 在该种子主页推荐区域实际出现的账号卡片 | 仅表示在该主页观察到推荐，不等于关注、合作、精准相似或相同受众 |

读取 [推荐卡片、来源边与深度](references/edges-and-recommendations.md) 再处理推荐路线或深度统计。音乐、特效、Following、评论及 Duet/Stitch 不属于默认必跑入口；若用户要增加这些路线，先明确可观察输入、预算、证据语义与真实执行支持，再由复盘保留可复用的实现。不要把代码存在当成页面路线已验证成功。

每条动作附父种子、原文/页面证据和有界预算。多个种子产生同一动作时只执行一次，保留全部来源；缓存可降低成本，不能虚增新增账号或深度。批量落盘后进入集中尾程，未审核新候选不直接递归。

## 共用执行器与集中尾程

本 Skill 复用第一 Skill 内置的 [运行库](../tiktok-seed-discovery/scripts/runtime/CONTRACT.md)，不复制第二套筛选器：

| 程序 | 用途 |
|---|---|
| `frontier.mjs` | 从 canonical 与有引文的审核结论生成一轮展开动作 |
| `browser.mjs` | 由 Eric Task Master 执行本轮页面动作并保存观察/checkpoint |
| `process.mjs` | 合并增量、生成评审队列与补资料动作，再合并 AI 审核和补查结果 |

真实 CLI 参数和 schema 以契约为准。编译前由 Agent 按发现价值、方向多样性和本轮目标排列审核种子；程序不自动替代语义排序。读取 [集中审核与数据处理](../tiktok-seed-discovery/references/shared-tail.md)，按「身份/作品/动作去重与标签聚类 → AI 内容与角色审核 → 粉丝/bio/地域补资料 → 必要作品和互动二筛 → 资格与发现价值分别判断」执行。

从共用运行库目录调用 `node frontier.mjs --config frontier-config.json` 和 `node process.mjs --config process-config.json`；相对配置路径按对应配置文件目录解析。已验证策略经 `frontier` 配置的 `policyFile` 接入，只调整符合门槛动作的路线优先级，不覆盖预算和审核条件。

`aiReviewFile` 与 `clusterReviewFile` 是 Agent 实际完成的原文审阅产物；缺审、证据无效或字段未核验保持待处理。补资料后重用同一 `process.mjs`，同 Brief 的历史通过 `priorCanonical` 合并；固定基线不随补资料改变。本人搜索样本不等于最近时间线。

运行目录、输出目录和 Task Master 配置从当前机器实际安装与任务配置解析。首次本机执行读取包内 [Task Master 最小运行手册](../tiktok-seed-discovery/references/taskmaster-operations.md)，本机已有 `eric-task-master` Skill 时同时采用其当前接入说明；没有独立依赖 Skill 也可按包内手册安装/定位执行器。沿用用户选择的 Profile，不使用作者电脑路径、固定用户名、固定国家或固定 Profile。同 Profile 浏览器动作串行，本地审核和聚类可并行。

## 以真实收益决定继续

按入口与来源种子报告历史新增身份、主题通过、资料覆盖、各画像条件通过/失败/未知、可展开新增、完整合格、重复与偏离，以及采集、补查、审核、重试和等待的成本。未测量的成本留空，原始作者吞吐不能外推为合格名单产能。

- **继续一轮：** 新种子/新线索有来源，净新增和主题收益支持；审核后再编译下一批。
- **先补筛：** 新增有价值但关键资料未知；优先补会影响决定的证据。
- **重找种子：** 重复饱和、主题漂移或方向不足；调用第一 Skill 更新有据查询。
- **结束或暂停：** 达到目标、预算或访问边界；交付证据和实际恢复点。

每次完成、暂停或失败后调用 [复盘与迭代](../tiktok-discovery-retrospective/SKILL.md)：review 生成报告后，分别检查 MD、执行器和策略，填写 iteration.json 并以 close 登记收尾。把路线收益、排除原因、覆盖缺口和执行问题抽象为可验证改进；按隔离副本、检查、版本安装和回滚流程发布。没有足够证据就保留原版并记录理由。下一轮重新加载 Skill 并固定 release.json 版本、实际执行模块哈希与策略快照。复盘不降低证据准入、不解除冷却、不把具体任务写进通用 Skill。用户已授权整个流程时自动衔接，不重复求许可。

保留原始作品/推荐出现记录、全部来源边、AI 审阅、补筛证据、排除/待查/中转处置、下一批动作和版本。逐方向报告真实无重复账号路径；六跳或千人目标按实际证据验收，轮次号、查询数、分页和缓存复用不能补深度。

只读开发不授权关注、点赞、私信或发布。验证、访问限制依 Task Master 等待或失败机制处理，保留 checkpoint，不切换 Profile 绕过。未出现推荐、未加载、加载失败、列表结束和预算停止分别记录；Worker 结束与业务覆盖完成分开。
