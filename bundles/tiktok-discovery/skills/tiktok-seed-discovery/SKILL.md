# TikTok 参考研究与种子发现

先研究客户给的参考，再用有出处的线索批量找新账号。这个 Skill 完成「需求收齐 → 参考深剖 → 批量发现 → 集中审核」；下一轮交给 [种子裂变](../tiktok-seed-expansion/SKILL.md)，每次运行结束或暂停后交给 [复盘与迭代](../tiktok-discovery-retrospective/SKILL.md)。三个 Skill 共用采集与处理代码，各自可以独立调用。

## 启动时一次收齐四项

先读当前对话与已有 Brief，只询问缺项，并把问题放在一条消息里。新方向开始采集前必须有：

| 信息 | 需要保存的内容 |
|---|---|
| 推广国家 | 一个或多个目标国家；将客户自然语言规范为 ISO 3166-1 alpha-2 代码，保留原话。推广市场、创作者所在地、受众国家分别记录 |
| 粉丝体量 | 明确上下界，规范成整数；不要把播放量当粉丝数 |
| 参考链接 | 3–5 条；每条由客户标为 `competitor`（竞品）、`brand_partner`（品牌已合作）、`style_reference`（希望合作的风格参考），可加备注 |
| 红人类别与风格 | 客户希望的类别、内容方式或风格描述；多类别可以并存，硬条件与偏好分开 |

已有内容不重复询问。客户提供不同数量、缺少参考或明确要跳过时，说明参考不足影响并按其明确选择执行，保留参考覆盖缺口；不能擅自补造参考或类型。客户只给“美国”时，它首先是推广市场，不能自行解释为已经确认创作者及受众都在美国。若地域资格会影响名单准入，集中确认或明确记录待确认项。

首次运行另读取 [运行库契约](scripts/runtime/CONTRACT.md) 和 [Task Master 最小运行手册](references/taskmaster-operations.md)；本机已有 `eric-task-master` Skill 时同时采用其当前接入说明。检查 Node、Task Master 与可用 Profile。沿用本任务已选择的 Profile，未指定时按最小手册使用既有默认或询问必要选择。运行路径从安装位置、任务工作目录和实际配置解析；不使用作者电脑路径、用户名或固定 Profile。缺少依赖先给出具体缺项，不能声称安装包独立包含浏览器、平台登录或 Task Master。

从本 Skill 目录运行 `node scripts/doctor.mjs` 可做只读依赖检查；有显式环境配置时使用 `node scripts/doctor.mjs --config environment.json`。配置与产物路径按契约解析，Agent 应先处理真实缺项，再启动浏览器。

向客户简短回显规范后的需求、参考数、时间窗口与首批预算。保存本次 `asOfUTC`，默认研究此前 **6 个日历月**，客户要求全年时使用 12 个月；恢复时沿用同一窗口。硬条件、预算和授权沿用现有上下文，不因进入下一阶段重复确认。

## 先把参考真正研究完

读取 [参考深剖与覆盖规则](references/reference-analysis.md)，用 `intake.mjs --input customer-brief.json --out jobs/current` 校验输入、形成参考采集计划，再通过 Task Master 执行独立的 `reference-browser.mjs` 入口；`reference-analysis.mjs --config reference-analysis-config.json` 组织证据和待评审材料，Agent 必须完成语义审阅后才能把结论交给搜索阶段。程序均位于 `scripts/runtime/`，真实输入、产物和完整操作顺序见 [运行库契约](scripts/runtime/CONTRACT.md)。

1. **解析参考身份。** 参考可以是 TikTok 主页或具体作品。作品链接先确认本人作者；同一作者只采一次，保留全部参考类型与备注。品牌主页是品牌线索源，不能直接当合格创作者。非 TikTok 链接、无法确认的作者或不可访问内容显式列待补。
2. **枚举窗口内公开作品。** 覆盖视频、照片等可读作品，保留分页与逐项证据。默认目标是窗口内全部可访问作品，不是每人固定 100 条。置顶、未知日期、非时间排序和预算停止都影响覆盖判断；未达到可靠边界时只能称部分采集。
3. **技术提取。** 保存真实可读的文案、标签、@ 对象、品牌/产品字样、公开商业披露、日期及可见指标。缺失字段保持缺失；不为文字采集逐条截图，只有风格判断、结构异常等需要视觉证据时才补看。
4. **AI 深剖。** 集中审核每个参考的主题、身份自述、场景、内容形式、风格证据、品牌关系和不应扩展的方向。客户标签与公开验证分别记录；把品牌提及当合作、把英语当美国、把孩子出镜当妈妈身份都不成立。
5. **交付研究底稿。** 形成逐参考档案、原始作品与覆盖说明、观察标签及聚类、带引文的品牌/账号关系、画像场景与负向边界，以及每条线索都有来源或明确推导说明的查询计划。无法完成的项进入缺口队列，不能用一段总结替代原始证据。

参考分析的作用是生成有质量的搜索材料。参考本人、品牌主页、品牌提到的账号、搜索发现的新作者分别记来源与角色；参考作者不计为本次“新找”的人。参考的知名程度、商业声明或粉丝体量不自动传递给相似候选。

## 用参考材料批量找种子

根据已审核的参考与 Brief 编译有限查询组，详见 [搜索组与批次边界](references/search-batches.md)。把真实标签、品牌/产品、身份地点、生活任务与内容形式组合成短查询；推导词注明推导来源，避免穷举全部词组。保留负向边界，防止品牌相关却目标人群完全不同的结果混入。

先批量读取视频搜索的真实作品卡片，记录作者、文案、标签、作品 ID/URL、可见指标、排序、观察时间和来源动作，再集中审核。不要按播放量只拿最火作品来代替目标粉丝区间；通过不同场景和表达增加中腰部覆盖，粉丝数在资料阶段核验。参考检索与新账号发现各自保留数量、时间和成本。

## 两个发现 Skill 共用尾程

按 [集中审核与数据处理](references/shared-tail.md) 调用同一运行库：

1. 稳定身份、作品和动作去重，保留所有来源边；聚类真实标签。
2. Agent 审阅原文，给主题、角色、偏离和待补结论；规则命中不能替代 AI 审核。
3. 给值得检查的账号批量补粉丝数、bio 和公开地域/商业证据。
4. 只补会改变决策的作品、互动或视觉缺口；保存采样范围，不把样本称全量。
5. 画像各项分别给 `pass/fail/unknown`，发现价值另给 `expand/pending/intermediary/stop`。中转与种子不等于合作合格。

未完成的步骤保留待处理状态。国家、受众、商业或风格必要条件尚未知时，不能计入完整合格名单；可见互动不能证明零假粉、真实成交或受众地域。

## 执行、交付与复盘

浏览器仅用 Eric Task Master。一个 Profile 串行执行浏览器动作，离线聚类和审核可以并行。先落观察与实体，再保存动作完成状态；保留 Task ID、版本、动作账本、业务 checkpoint 与恢复原因。验证、搜索限制、未加载、不可见、列表结束和预算用完分别记录，不通过换账号/Profile 或重复请求绕过限制。

交付 Brief、参考档案与覆盖、证据支撑的搜索计划、原始作品、去重账号、AI 审核、资料/二筛证据、可展开种子、排除/待补队列及来源图。原始观察、身份去重新增、主题通过、各资格条件、可展开和完整合格分别计数。首次搜索发现的根账号深度为 0；参考推导的关系按真实来源记录，不靠阶段编号增加深度。

每次完成、暂停或明确失败后，调用 [复盘与迭代 Skill](../tiktok-discovery-retrospective/SKILL.md)，运行 review 并分别检查 MD、执行器和策略，填完 iteration.json 后以 close 登记收尾；没有需要更新的证据也要记录保留原版的理由。有改进时经隔离副本、验证、版本安装与回滚流程发布。下次启动重新加载三个 Skill，记录 release.json 版本及实际执行模块哈希；只采用已验证且适用的通用能力，不把具体国家、品牌、账号、关键词或客户结论写进默认值。暂停时只做离线复盘，保留冷却和验证边界。

有可靠新种子则继续 `tiktok-seed-expansion`；主要缺资料则先补筛；方向不足则更新有据的查询计划。用户已授权整个流程时继续工作，不在两个 Skill 的交接处再次索要许可。
