# 集中审核与数据处理

种子发现与每轮裂变使用相同程序和证据规则，补资料后再运行同一处理器。真实参数、schema 和产物名见 [运行库契约](../scripts/runtime/CONTRACT.md)。

## 数据合并

`process.mjs` 合并 Task Master 产物、同 Brief 的 `priorCanonical` 与 AI 审核文件；AI 作者审核经 `aiReviewFile` 接入，标签分组经 `clusterReviewFile` 接入。语义判断由 Agent 审阅本人原始文案/bio 后产生；正则、词频、聚类候选、模型未审队列均不能记为主题通过。

处理配置的相对路径按配置文件目录解析。用 `taskOutputs` 将真实 Task ID 映射到实际 output 目录，或给显式 `taskRoot` 读取离线任务包；未提供时先配置，不猜本机 Task Master 存储路径。从运行库目录调用 `node process.mjs --config process-config.json`；配置中只使用本轮实际 Task ID 和目录。

保持固定发现基线，包含此前全部观察的候选、中转和参考账号；补资料任务不改写基线、抹掉本轮新增。按稳定平台 ID 合并无歧义身份；只有 handle 时注明未确认身份，显示名不作为合并依据。保留改名/别名、冲突、作品归属和全部来源边；handle 记录数与身份去重数分开报告。

## 两次集中筛选

第一筛用实际内容判断主题、账号角色和明确偏离，分别记录原因与本人证据。标签簇名称与准入建议由 Agent 审核，不能从查询命中倒推主题通过。

第二筛先批量补值得检查者的主页，保存粉丝原文/解析值及时间、bio、公开地域与商业入口，再补会改变判断的本人作品或互动/视觉样本。无作品的推荐卡片可直接补主页；缺作品不等于不合格。

对每个 Brief 必需条件保存 `pass/fail/unknown` 与证据引用；粉丝缺失、确实超范围、资料不可见分别记录。推广国家本身不证明创作者或受众在当地。以运行库支持的国家字段与本轮配置核验，不能把美国判断硬套其他国家；含糊地点由 Agent 结合本人证据审查，无法判断就 unknown。

本版 Brief 使用 `countries` 或 `targetCountries` 的 ISO 两字母代码数组（兼容单项 `country`），审核的 `country` 为创作者所在地 ISO 代码或 `unknown`。多国地点词用 `locationTermsByCountry`，或以 `locationCues` 显式关联 `{country,pattern,label}`；单国的 `locationTerms` 归属当前目标。只有本人 bio 的明确地点线索及有效引文才能支持所在地通过；这些规则不核验受众国家。

新需求默认 `countryMeaning:promotion_market`，只说明推广市场；所在地匹配不能自动变成市场资格通过，异国所在地也不自动否决市场适配。当前程序的 `marketCountryStatus` 保持 unknown，需独立受众/市场证据流程补审。明确要求创作者所在地时才用 `creator_location`。`creatorLocationMatch`、`marketCountryStatus`、`qualificationCountryStatus` 分别记录这些判断；兼容字段 `targetCountryStatus` 仅表示所在地匹配。

互动样本保留可用指标、公式、样本数、选择方法、日期与排序状态；播放量缺失不能按零作分母。未确认最近排序就称“可见样本”；窗口采集不完整时不要给无条件全量更新频率。本人搜索样本不等于完整时间线。风格需相应视觉或内容证据；文字/互动不能认证真实受众、销量或零假粉。

## 资格与展开价值独立

- `expand`：主题与具体线索足以支持下一轮，必要资格可能仍待查。
- `pending`：关键证据缺口影响决定，先补材料。
- `intermediary`：本身不是目标合作对象，但有可引用的有效发现线索。
- `stop`：无关或无可用线索，保留排除理由供下一批改进。

品牌、机构或超粉丝范围账号可有中转价值；发现价值不能覆盖任何资格失败。完整合格数仅包括用户全部必要条件已由证据通过的身份，不是 `expand` 数、粉丝通过数或评分超过某阈值的数量。

## 产物与效率

保留 canonical、原始作品、标签聚类、审核队列、种子、资料补查动作及 summary 等当前契约产物。每次报告原始观察、历史新增身份、主题通过、资料覆盖、粉丝通过/未知、各地域/商业/风格状态、可展开与完整合格。不同路线命中同一身份总体只计一次，同时保留多来源。

绩效包含采集、补查、审核、失败重试及等待的实际成本；未测量不填造值。排除理由与未解决缺口同时输入下一轮与复盘。目标达成、预算到达、访问受限和普通 Worker 结束分别记录；执行器返回成功不代表业务覆盖完整。
