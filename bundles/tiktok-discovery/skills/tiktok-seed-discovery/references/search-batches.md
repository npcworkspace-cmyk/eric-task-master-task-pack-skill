# 搜索组与批次边界

搜索计划接收参考研究产物与当前 Brief，不把一批行业热词当成深剖结果。每条查询保留「来源参考/作品/原文 → 观察线索或推导 → 查询 → 负向边界」；自然语言推导不伪装成账号实际使用过的标签。

| 搜索组 | 查询依据 | 判断边界 |
|---|---|---|
| 标签与主题 | 参考本人内容的真实标签、经过 AI 审核的主题簇 | 同标签不证明合作、同受众或同地点；泛标签单独低优先 |
| 品牌与产品 | 真实名称、竞品线索、明确的使用或商业披露 | 保留关系类型；品牌提及仍可能来自新闻、批评、官方号或普通用户 |
| 问题与生活场景 | 参考中反复出现的任务、障碍、使用环境 | 复用场景机制，避免只有品牌词的热门结果 |
| 身份与地点 | 本人自述以及客户所需的身份/地域表达 | 搜索命中仅定位线索，资格需本人证据；受众地域另查 |
| 内容方式与风格 | 可引用的讲解方式、演示场景、已观察视觉证据 | 文案风格和画面风格分开，未观看不声称视觉已通过 |

选择互有区别的短查询而非全部词的笛卡尔积。根据线索具体程度、与需求关系、来源独立性和方向多样性安排首批，再按实际新作者与主题通过率追加。单条参考贡献的大量相似标签不能当成多个独立方向。

中腰部账号可能不在热门榜前列。用不同问题、产品使用场景、身份语言与可见搜索筛选增加覆盖；排序/筛选只有页面实际支持并成功使用时才记录生效。播放量不能代替粉丝范围，关键词中加入粉丝数字不构成可靠粉丝筛选。

每条动作有明确数量、滚动、时间和重试预算，保存规范化路线、查询/URL、排序、筛选、时间窗口、采集上下文、来源列表、状态及 checkpoint。当前实现的动作去重字段以 [运行库契约](../scripts/runtime/CONTRACT.md) 为准；不能仅改一个未参与动作键的元数据就声称新执行。需要重新验证、换窗口或恢复部分分页时保存新原因和与旧动作的关系。

同一查询被多个参考或种子产生，只执行一次并保留多条来源边。历史基线包含全部已观察候选与中转，不能只拿最终入围表去重。结果持续有新增且主题收益支持时才加预算；加载失败与真实无新增分别记录，未启动、部分成功、预算停止和列表结束不能统一记零。

共用尾程见 [集中审核与数据处理](shared-tail.md)。报告各组新增身份、主题通过、可展开种子、完整合格及包含等待/补查/审核的成本；没有测量的成本留空。批次结果可以影响下一批预算，未经独立验证的改进保存在复盘候选，不直接升级通用 Skill。
